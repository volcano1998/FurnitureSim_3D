Hook: everyone has been stuck on a staircase with a couch. Today we'll build a tool that answers 'does it fit?' — and I'll show you how the planner works inside.
The problem

Moving a couch is a 6-dimensional puzzle

  • It slides in 3 directions: x, y, z
  • It spins in 3 ways: yaw, pitch, roll
  • Walls, corners and doorways don't care how clever you are
  • "Does it fit?" really means: is there a collision-free path through 6-D space?
The key idea: a rigid box has six degrees of freedom. A path is a sequence of poses. Fit means such a path exists.
What you'll see

One app, three ways to answer it

3D room editor

Rooms are boxes defined by an origin and three edge vectors. Stretch, skew, add, connect.

Two auto-solvers

A probabilistic one (RRT-Connect) and a deterministic straight-shot heuristic.

Manual mode

Hold M, drag the furniture yourself. The app tells you when you collide.

Hands-on · Step 1

Build the room

  1. Drag the A / B / C length sliders. Try 8 · 2.4 · 2.4 — instant hallway.
  2. Change the angles to skew it, or hit the 45° two-face box template.
  3. Need a turn? + Add object → Connect two objects → click a face on each.
Every room is a box: O + s·A + t·B + u·C, with s, t, u from 0 to 1. Turn on vector labels to see A, B, C.
Live: drag sliders, show labels, add a second object and connect. Mention drag to move blocks, drag empty space to orbit.
Hands-on · Step 2

Choose the entrance & exit

  1. Press Pick faces in 3D view.
  2. Click an outside wall: first the entrance, then the exit. (Or use the dropdowns.)
  3. Press Confirm 3D model — the room locks.
Only these two faces are doorways. Every other wall stays solid — the furniture can't cheat through them.
Changed your mind later? Click step 1 or 2 in the stepper to unlock the room again.
Hands-on · Step 3

Describe the furniture

  1. Enter Length · Width · Height. Try 2.5 · 1.2 · 1.2.
  2. The green box is your furniture, parked beside the room. Show furniture in 3D view to focus it.
  3. Set Clearance (0.1) — a safety margin around every side.
Furniture is one rigid box. Clearance grows the box in every direction before any collision check.
The preview only shows in step 3 so it doesn't clutter the other steps. Units are whatever units the room uses.

  2. Hold M and drag. Use the sliders for height, yaw, pitch, roll.
  3. Stuck at a corner? Auto Pilot: click a furniture edge, then a room edge — they snap parallel.

How do we find a path?

Switch gears: from using it to understanding it. Three questions, three slides, then the two solvers.
Technique · 1

A position is six numbers

// furniture pose { x, y, z, yaw, pitch, roll }
  • 3 to translate, 3 to rotate
  • Rotations use Euler order ZYX, converted to a quaternion
  • Allow roll sampling off? The search drops to 5-D — faster
poseQuaternion in planner.js builds the rotation. We use ZYX order everywhere so rendering, collision and saving agree.
Technique · 2

Is this pose legal?

  • The room is a union of boxes. A point is inside if p = O + sA + tB + uC with s, t, u ∈ [0, 1]
  • Furniture is sampled on its shell: a 5×5×5 grid minus the interior = 98 points, grown by clearance
  • Every point must be inside the room
  • Between two poses we interpolate and check every step
  • Crossing a wall is allowed only through the entrance / exit polygon
isPoseValid in planner.js. Simple, brutally effective: sample the shell, test each point against each box. The same check backs manual mode and both solvers — nobody gets special treatment.
Technique · 3

RRT-Connect: grow two trees until they meet

  1. One tree grows from the start, one from the goal
  2. Pick a random pose (the ✕). Step the nearest node toward it — if the edge is legal, keep it
  3. Then the other tree greedily chases that new node (up to 160 steps)
  4. Trees touch → path found. Smooth it, resample it, animate it
Probabilistic: finding a route proves it fits — failing doesn't prove it can't. Run it again or raise iterations. We never "fix" failures by quietly shrinking clearance.
Step sizes: position step is the smallest room dimension divided by 28, angle step is 4 degrees. Every edge is validated with the collision check from the last slide.
Technique · 4

Smart starts beat pure luck

Random sampling alone rarely threads a tight doorway. So we seed the search:

  1. Sample offsets across the opening × 15° yaw/pitch/roll orientations
  2. Refine the promising ones at 5°
  3. Probe inward: how deep does each candidate get?
  4. Rank by depth, clearance, alignment, offset, tilt
  5. Feed the top poses as many starts and goals
Default is to sample up to 2000 orientations per opening. This is what makes the difference between 'sometimes works' and 'usually works'.
Technique · 5

The straight-shot heuristic

  1. Travel direction = the block edge not in the entrance face
  2. Point the furniture's longest axis along it
  3. Project the doorway along that direction: does the cross-section (with clearance) fit?
  4. Centre it, stage it outside, slide straight in
Deterministic, instant, and when it fails it names the checkpoint where it got stuck. Multi-block rooms hand off between blocks with a short RRT.

Technique · 6

You + planner = hybrid

  1. Get the furniture fully inside by hand (Auto Pilot helps)
  2. Press Continue with solver
  3. The planner starts from your exact pose and finds the rest

Humans are great at the awkward entrance. Planners are great at the long middle.

Honest limits

  • Furniture is a single box
  • Rooms are connected boxes (no curves)
  • Rigid only: no tilting-by-bending, no taking legs off
  • RRT is probabilistic
Be upfront about what this is: a fast feasibility estimate, not a CAD-grade guarantee.
